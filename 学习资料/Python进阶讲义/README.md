# Python 零基础进阶讲义（通俗版）

这套讲义不是“术语词典”，而是一条可以照着动手的学习路线。每份讲义都尽量回答同一组问题：

1. 这个东西是什么？
2. 为什么需要它？
3. 最小例子怎么写？
4. 每一行代码在做什么？
5. 出错时先看什么？
6. 怎么判断自己是否真的会了？

> 学习原则：先理解，再模仿；先跑通成功路径，再故意制造错误；最后关掉讲义重写一遍。只“看懂”不等于会写。

## 二、统一练习环境

Python 代码统一在下面的 VS Code 工作区中练习：

```text
E:\Project\0基础学agent\实战项目\python-foundation
```

只打开单个 `.py` 文件还不够，要打开整个 `python-foundation` 文件夹。这样虚拟环境、模块导入和 pytest 才能被正确识别。

每次练习按这个循环：

1. 在 `exercises/` 新建 `.py` 文件。
2. 先自己敲代码，不急着复制。
3. `Ctrl+S` 保存。
4. `Ctrl+F5` 运行，在终端查看结果。
5. 故意改错一次，阅读报错最后一行。
6. 用 `F9` 设置断点，按 `F5` 调试，观察变量。
7. 写进 `tests/test_*.py`，运行 pytest。
8. 修好后重写一遍，不照着看。
9. 用 Source Control 提交 Git。

## 三、这套讲义的写法

每个知识点尽量按下面的顺序出现：

```text
生活类比
→ 一句话定义
→ 最小代码
→ 逐行解释
→ 成功和失败两条路径
→ 练习题
→ 常见错误
→ 自检问题
```

如果某一段还是看不懂，不要继续硬背。把具体是哪一句、哪一行代码不懂告诉 Codex，再把它拆成更小的例子。

## 四、学习时始终分清四件事

| 名称 | 通俗解释 |
|---|---|
| 项目文件夹 | 一整个工作台，里面有代码、数据、测试和配置 |
| 终端 | 输入命令、执行 Python 和测试的地方 |
| Python 解释器 | 真正执行代码的“大脑”，必须选择 `.venv` 里的那个 |
| 虚拟环境 `.venv` | 这个项目专用的工具箱，避免不同项目的依赖互相污染 |

这四件事弄混时，常见表现不是代码错，而是 VS Code 用了错误的 Python、找错路径或看不到测试。

## 五、遇到问题时怎样提问

不要只写“报错了”。尽量提供：

- 你正在做哪一课、哪一节。
- 你期望发生什么。
- 实际发生什么。
- 完整报错文字或截图。
- 你已经尝试过什么。

这样可以直接从问题所在处继续，不需要从头重讲。

## 六、讲义内容没有变少

通俗版会减少不必要的术语堆叠，但不是删掉知识范围。原有的文件读写、异常、模块、类、类型校验、HTTP、异步、pytest、Git 和三个项目都会保留。改写重点是：

- 先说人话，再给正式名称。
- 不把多个新概念塞进一行。
- 每个函数尽量逐行解释。
- 明确成功路径和错误路径。
- 明确“现在应该动手做什么”。

学习档案仍记录在项目根目录的 `学习进度.md`。掌握状态只依据你能否独立完成和解释，不依据是否看过讲义。
