# 一、文件读写

## 1. 为什么需要文件

程序里的变量像写在草稿纸上。程序一退出，草稿纸就没了。

例如：

```python
name = "小明"
```

只要 Python 程序结束，这个 `name` 就消失了。

文件像正式的笔记本，可以把内容保存到磁盘。下次程序启动时，还能重新读出来。

常见文件用途：

| 类型 | 示例 | 用途 |
|---|---|---|
| 文本 | `.txt`、`.md` | 保存普通文字 |
| 配置 | `.toml`、`.env` | 保存程序设置 |
| 数据 | `.json` | 保存结构化数据 |
| 二进制 | 图片、音频、压缩包 | 保存不是文本的数据 |

## 2. 先分清“路径”和“文件”

下面这行只是创建一个“路径对象”，不会创建磁盘文件：

```python
from pathlib import Path

path = Path("data") / "notes.txt"
```

用生活类比：

- `Path("data") / "notes.txt"` 像写了一张地址条。
- 它描述了“文件应该在哪里”。
- 但它还没有真的创建文件。

查看路径信息：

```python
print(path)          # data\notes.txt
print(path.parent)   # data
print(path.name)     # notes.txt
print(path.stem)     # notes
print(path.suffix)   # .txt
```

常用判断：

```python
path.exists()   # 路径所指的东西存在吗
path.is_file()  # 它是文件吗
path.is_dir()   # 它是目录吗
```

得到绝对路径：

```python
print(path.resolve())
```

## 3. 第一个文件读写例子

新建 `exercises/files_and_exceptions/01_io.py`：

```python
from pathlib import Path

path = Path("data") / "hello.txt"

# 1. 创建父目录
path.parent.mkdir(parents=True, exist_ok=True)

# 2. 写入文字
path.write_text("你好，Python\n", encoding="utf-8")

# 3. 读回文字
text = path.read_text(encoding="utf-8")

print("文件位置：", path.resolve())
print("文件内容：", text)
```

逐行解释：

1. `from pathlib import Path`：导入表示路径的工具。
2. `Path("data") / "hello.txt"`：用 `/` 拼接目录和文件名。
3. `path.parent`：得到 `Path("data")`。
4. `.mkdir(...)`：创建目录。
5. `parents=True`：如果 `data` 的上级目录也不存在，一起创建。
6. `exist_ok=True`：如果目录已经存在，不报错。
7. `write_text(...)`：把字符串写进文件。
8. `encoding="utf-8"`：明确使用 UTF-8 编码，中文更稳定。
9. `read_text(...)`：读取文件并把内容变成字符串。

注意：`write_text()` 会创建文件，`mkdir()` 只创建目录。

### 路径为什么会写错

相对路径：

```python
Path("data") / "notes.txt"
```

它是相对于“程序当前运行目录”的。

绝对路径：

```python
Path(r"E:\Project\0基础学agent\实战项目\python-foundation\data\notes.txt")
```

它从盘符开始，只指向一个固定位置。

当脚本要读取自己旁边的文件时，可以这样写：

```python
BASE_DIR = Path(__file__).resolve().parent
DATA_FILE = BASE_DIR / "data" / "notes.txt"
```

- `__file__`：当前 Python 文件的路径。
- `.resolve()`：得到更完整的绝对路径。
- `.parent`：当前文件所在目录。
- 再从当前文件目录拼接 `data/notes.txt`。

这种方式不容易受“从哪个终端目录启动”影响。

## 4. 文件模式

使用 `path.open()` 时，需要选择模式：

| 模式 | 通俗解释 | 文件不存在时 |
|---|---|---|
| `r` | 只看不写 | 报错 |
| `w` | 重新写，先清空旧内容 | 创建 |
| `a` | 在末尾追加 | 创建 |
| `x` | 只有不存在时才创建 | 创建 |
| `rb` / `wb` | 读写二进制内容 | 取决于操作 |

最危险的是 `w`：

```python
path.open("w", encoding="utf-8")
```

它一打开就可能清空原文件。重要数据不要直接覆盖，先写临时文件。

逐行读取大文件：

```python
with path.open("r", encoding="utf-8") as file:
    for line in file:
        print(line.rstrip("\n"))
```

`with` 的作用：

- 进入代码块时打开文件。
- 离开代码块时自动关闭文件。
- 即使中间报错，也会尽量关闭。

可以把 `with` 想成进入房间后自动关门，不需要每次记得手动关。

## 5. JSON 到底是什么

先不要把它和 Python 字典混为一谈。

### Python 对象在内存里

```python
data = {
    "name": "小明",
    "skills": ["Python", "Git"],
}
```

这是 Python 字典，程序可以直接用：

```python
print(data["name"])
```

### JSON 是文本格式

同一个信息写成 JSON，可能长这样：

```json
{
  "name": "小明",
  "skills": ["Python", "Git"]
}
```

它看起来像字典，但本质是“按 JSON 规则排列的一段文字”，可以保存进 `.json` 文件，也可以通过网络发送。

### 为什么需要转换

因为：

- Python 程序使用字典、列表等对象。
- 文件和网络通常传字符串。

所以两边需要来回转换：

```text
Python 字典 --dumps--> JSON 字符串 --write_text--> .json 文件
Python 字典 <--loads-- JSON 字符串 <--read_text-- .json 文件
```

- `json.dumps`：Python 对象转成 JSON 字符串。
- `json.loads`：JSON 字符串转回 Python 对象。
- 最后的 `s` 可以记成 `string`，表示处理字符串。

最小例子：

```python
import json

data = {
    "name": "小明",
    "skills": ["Python", "Git"],
}

text = json.dumps(data, ensure_ascii=False, indent=2)
print(type(text))  # <class 'str'>
print(text)

decoded = json.loads(text)
print(type(decoded))     # <class 'dict'>
print(decoded["skills"]) # ['Python', 'Git']
```

参数含义：

- `ensure_ascii=False`：让中文直接显示。
- `indent=2`：每层缩进两个空格，方便阅读。
- 参数只影响文本排版，不改变数据含义。

### 保存 JSON 到文件

```python
import json
from pathlib import Path


def save_json(path: Path, data: object) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)
    text = json.dumps(data, ensure_ascii=False, indent=2)
    path.write_text(text, encoding="utf-8")
```

执行顺序：

```text
创建目录
-> 把 Python 对象 dumps 成 JSON 文字
-> write_text 写入文件
```

### 从文件读 JSON

```python
def load_json(path: Path) -> object:
    text = path.read_text(encoding="utf-8")
    return json.loads(text)
```

执行顺序：

```text
read_text 读取文字
-> loads 解析成 Python 对象
-> return 返回给调用者
```

### JSON 和 Python 的语法区别

| JSON | Python |
|---|---|
| `true` | `True` |
| `false` | `False` |
| `null` | `None` |
| 字符串必须双引号 | 单引号、双引号都可 |
| 最后一个字段后不能随手加逗号 | 也不推荐，但部分结构允许 |

如果 JSON 格式错了，例如：

```json
{bad json
```

`json.loads()` 会抛 `json.JSONDecodeError`。

### 不能直接变成 JSON 的 Python 对象

JSON 只能表达：

- 对象 `{}`
- 数组 `[]`
- 字符串
- 数字
- `true` / `false`
- `null`

不能直接处理：

- `set`
- `datetime`
- 自定义类对象

需要先转换：

```python
raw_set = {1, 2, 3}
JSON 可用的是 list(raw_set)
```

```python
from datetime import datetime

time_text = datetime.now().isoformat()
```

含义是：把复杂对象先变成 JSON 支持和保存的简单值。

## 6. 安全写入 JSON

假设直接覆盖旧文件：

```python
path.write_text(new_text, encoding="utf-8")
```

如果写到一半程序崩溃，原来的重要数据可能已经被破坏。

安全写入的步骤：

1. 先把新内容写进 `xxx.json.tmp`。
2. 确认临时文件写完。
3. 用临时文件替换正式文件。

```python
def atomic_save_json(path: Path, data: object) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)

    temp = path.with_suffix(path.suffix + ".tmp")
    temp.write_text(
        json.dumps(data, ensure_ascii=False, indent=2),
        encoding="utf-8",
    )

    temp.replace(path)
```

假设：

```text
path = account.json
temp = account.json.tmp
```

`temp.replace(path)` 成功后，`account.json.tmp` 变成新的 `account.json`。

这里的“原子”不是魔法，而是尽量保证：正式文件不会处于“只写了一半”的状态。

# 二、异常处理

## 1. 异常是什么

异常是“程序无法按原计划继续”的信号。

可以把异常想成火警：

- 正常时没有火警。
- 出现问题时会响。
- 你可以选择处理它。
- 也可以让它继续向上报警，而不是假装没看见。

常见异常：

| 异常 | 通常什么时候出现 |
|---|---|
| `FileNotFoundError` | 文件不存在 |
| `PermissionError` | 没有权限 |
| `JSONDecodeError` | JSON 格式不对 |
| `ValueError` | 值的格式或范围不合适 |
| `KeyError` | 字典里没有这个键 |
| `IndexError` | 列表下标超出范围 |
| `TypeError` | 类型用错 |
| `TimeoutError` | 等待超时 |
| `OSError` | 文件或系统操作失败的常见父类 |

不处理异常时，Python 会打印 traceback，然后程序停止。

处理异常的目标不是“让报错消失”，而是：

- 能恢复时恢复。
- 不能恢复时给出清楚信息。
- 保留原因，方便排查。

## 2. 异常处理四块

```python
try:
    number = int("abc")
except ValueError as exc:
    print(f"输入不是整数：{exc}")
```

含义：

- `try`：先尝试执行可能有风险的代码。
- `except`：如果出现对应异常，执行这里。
- `exc`：保存这次异常的具体信息。

完整结构：

```python
try:
    result = 10 / 2
except ZeroDivisionError:
    print("除数不能为 0")
else:
    print("try 成功，结果是", result)
finally:
    print("本次尝试结束")
```

执行顺序：

```text
先执行 try
-> 如果 try 没异常，执行 else
-> 如果 try 有匹配异常，执行对应 except，跳过 else
-> 最后无论成功还是失败，执行 finally
```

注意：

- `else` 不是循环的 `else`。
- `try` 不是循环。
- `finally` 不代表一定成功，它代表“一定会执行到这里”。

### 文件存在和不存在的对比

```python
from pathlib import Path

path = Path("data") / "missing.txt"

try:
    text = path.read_text(encoding="utf-8")
except FileNotFoundError:
    print("A：文件不存在")
else:
    print("B：读取成功")
finally:
    print("C：本次尝试结束")
```

文件不存在：

```text
try 产生 FileNotFoundError
-> except 打印 A
-> 跳过 else
-> finally 打印 C
```

输出：

```text
A：文件不存在
C：本次尝试结束
```

文件存在：

```text
try 成功
-> 执行 else 打印 B
-> finally 打印 C
```

输出：

```text
B：读取成功
C：本次尝试结束
```

## 3. 不要抓住所有异常然后沉默

不推荐：

```python
try:
    data = json.loads(text)
except:
    pass
```

原因：

- 它会把真正的代码 bug 也吞掉。
- 它会把键盘中断等一起隐藏。
- 你不知道到底发生了什么。

应该只捕获能处理的异常：

```python
try:
    data = json.loads(text)
except json.JSONDecodeError as exc:
    print(
        f"JSON 错误：第 {exc.lineno} 行，"
        f"第 {exc.colno} 列：{exc.msg}"
    )
```

如果当前层不能处理，可以补充上下文后重新抛出：

```python
try:
    text = path.read_text(encoding="utf-8")
except OSError as exc:
    raise RuntimeError(f"读取配置失败：{path}") from exc
```

`from exc` 保留原始异常，排查时不会丢掉根因。

## 4. 自定义异常

当项目有自己的业务规则时，可以定义更明确的异常：

```python
class LedgerError(Exception):
    """账本业务错误的基类。"""


class InvalidAmountError(LedgerError):
    """金额不合法。"""


def parse_amount(text: str) -> int:
    try:
        cents = int(text)
    except ValueError as exc:
        raise InvalidAmountError("金额必须是整数分") from exc

    if cents <= 0:
        raise InvalidAmountError("金额必须大于 0")

    return cents
```

`raise` 的意思是主动抛出异常，而不是继续返回一个错误结果。

异常类通常以 `Error` 结尾。底层函数抛出具体原因，上层统一转成用户能理解的提示。

## 5. 退出码

命令行程序结束时可以返回退出码：

```python
def main() -> int:
    try:
        run()
    except LedgerError as exc:
        print(f"操作失败：{exc}")
        return 1
    return 0


if __name__ == "__main__":
    raise SystemExit(main())
```

含义：

- `0`：成功。
- 非 `0`：失败。
- 终端脚本、自动化工具和 CI 会据此判断程序是否失败。

# 三、模块与包

## 1. 为什么不能把所有代码写在一个文件

小脚本时，一个文件很方便。项目变大后，一个文件会出现：

- 函数太多，很难找。
- 文件读写、业务规则、命令行混在一起。
- 改一处容易影响另一处。
- 测试困难。

模块和包就是给代码分柜子。

## 2. 名词解释

| 名称 | 通俗解释 | 例子 |
|---|---|---|
| 模块 | 一个 `.py` 文件 | `storage.py` |
| 包 | 装多个模块的目录 | `ledger/` |
| 脚本 | 直接运行的文件 | `main.py` |
| 库 | 别人写好、可以复用的模块集合 | `httpx` |

结构示例：

```text
ledger/
├─ __init__.py
├─ models.py
├─ storage.py
├─ service.py
└─ cli.py
```

职责：

- `models.py`：数据长什么样。
- `storage.py`：负责保存和读取。
- `service.py`：业务规则。
- `cli.py`：命令行参数和打印。
- `__init__.py`：告诉 Python 这是一个包；可以为空。

## 3. 导入模块

三种常见方式：

```python
import json
```

使用：

```python
json.loads(text)
```

只导入某个名字：

```python
from pathlib import Path
```

使用：

```python
path = Path("data")
```

包内导入：

```python
from ledger.models import Transaction
from .storage import save_transactions
```

相对导入中：

- `.` 表示当前包。
- `..` 表示上一级包。

不要用：

```python
from module import *
```

这种方式看不出名字从哪里来，也容易覆盖已有变量。

## 4. 程序入口保护

推荐每个可运行模块都写：

```python
def main() -> None:
    print("程序开始")


if __name__ == "__main__":
    main()
```

直接运行这个文件时：

```text
__name__ == "__main__"
```

所以会执行 `main()`。

被其他文件导入时：

```text
__name__ == "ledger.cli"
```

所以不会自动执行 `main()`。

包内程序优先用模块方式运行：

```powershell
python -m ledger.cli
```

它比直接执行 `python ledger/cli.py` 更容易正确处理相对导入。

## 5. 循环导入

如果：

- `a.py` 导入 `b.py`
- `b.py` 又导入 `a.py`

就可能形成循环导入。

解决方向：

1. 把两者都需要的模型放到第三个模块。
2. 重新分层，明确依赖方向。
3. 实在无法避免时，才考虑在函数内部延迟导入。

不要用不断加 `import` 的方式碰运气。

## 6. 依赖和虚拟环境

创建环境：

```powershell
python -m venv .venv
```

安装依赖：

```powershell
& ".\.venv\Scripts\python.exe" -m pip install pydantic httpx pytest
```

生成依赖清单：

```powershell
& ".\.venv\Scripts\python.exe" -m pip freeze > requirements.txt
```

通常：

- `.venv/` 不进 Git。
- `requirements.txt` 或 `pyproject.toml` 进 Git。

原因是 `.venv` 很大且和本机相关，依赖清单才方便别人重建环境。

# 四、类和 dataclass

## 1. 类是什么

类是“模板”，对象是按模板造出来的具体东西。

生活类比：

- 类是房屋设计图。
- 对象是一栋具体建好的房子。
- 不同房子可以有不同的门牌号和住户。

代码示例：

```python
class Transaction:
    def __init__(
        self,
        amount_cents: int,
        note: str,
        kind: str = "expense",
    ) -> None:
        self.amount_cents = amount_cents
        self.note = note
        self.kind = kind

    def signed_amount(self) -> int:
        if self.kind == "income":
            return self.amount_cents
        return -self.amount_cents

    def describe(self) -> str:
        yuan = abs(self.signed_amount()) / 100
        sign = "+" if self.signed_amount() > 0 else "-"
        return f"{sign}{yuan:.2f} 元  {self.note}"
```

创建一个对象：

```python
transaction = Transaction(3000, "午餐")
print(transaction.describe())
```

名词：

- `class`：定义模板。
- `Transaction`：类名。
- `transaction`：具体的对象。
- `self`：当前这个对象。
- 属性：对象保存的数据，例如 `amount_cents`、`note`。
- 方法：绑定在对象上的函数，例如 `describe()`。
- `__init__`：创建对象时执行的初始化方法。

## 2. 为什么需要 `self`

```python
def signed_amount(self) -> int:
    return -self.amount_cents
```

每个对象都有自己的 `amount_cents`。

当程序执行：

```python
transaction.signed_amount()
```

Python 会把 `transaction` 作为 `self` 传进来，所以方法才能读取这个对象自己的数据。

## 3. 可变默认值陷阱

错误写法：

```python
class Bad:
    items = []
```

`items` 在类级别共享，所有实例可能一起改它。

如果对象自己的列表应该默认独立，要写成：

```python
class Example:
    def __init__(self) -> None:
        self.items: list[str] = []
```

## 4. 继承：是一种

继承适合表达“它是某种东西”。

```python
class Animal:
    def __init__(self, name: str) -> None:
        self.name = name

    def speak(self) -> str:
        raise NotImplementedError


class Dog(Animal):
    def speak(self) -> str:
        return f"{self.name}：汪"


class GuideDog(Dog):
    def __init__(self, name: str, owner: str) -> None:
        super().__init__(name)
        self.owner = owner
```

- `Dog` 是一种 `Animal`。
- `GuideDog` 是一种 `Dog`。
- `super()` 表示调用父类的实现。

不要在层级很深时硬用继承。为了复用几行代码搭建很多层，会让代码更难理解。

## 5. 组合：拥有一个

组合表达“一个对象里面使用了另一个对象”。

```python
class ApiClient:
    def fetch(self) -> dict:
        return {"ok": True}


class ReportService:
    def __init__(self, client: ApiClient) -> None:
        self.client = client

    def build(self) -> str:
        return str(self.client.fetch())
```

`ReportService` 不“是一种” `ApiClient`，它只是“拥有一个”客户端工具。

实际写项目时，组合往往比深层继承更清楚。

## 6. dataclass：专门减少样板代码

普通类经常要写很多 `__init__`。如果这个类主要用途是保存数据，可以用 `@dataclass`：

```python
from dataclasses import dataclass, field


@dataclass
class Transaction:
    amount_cents: int
    note: str
    kind: str = "expense"
    tags: list[str] = field(default_factory=list)


first = Transaction(3000, "午餐")
second = Transaction(3000, "午餐")

print(first)
print(first == second)
```

装饰器效果：

- 自动生成 `__init__`。
- 自动生成方便打印的 `__repr__`。
- 自动生成按字段比较的 `__eq__`。

### 为什么不能写 `tags: list[str] = []`

如果多个对象共用同一个列表，一个对象追加数据，另一个也会被影响。

正确写法：

```python
tags: list[str] = field(default_factory=list)
```

`default_factory=list` 的意思是：每个新对象调用一次 `list()`，得到自己的空列表。

### 创建后禁止修改

```python
@dataclass(frozen=True)
class Point:
    x: int
    y: int
```

`frozen=True` 表示创建后不能重新给 `x`、`y` 赋值。

适合表示不应该被随便修改的数据。

### 初始化后校验

```python
@dataclass
class Timer:
    seconds: int

    def __post_init__(self) -> None:
        if self.seconds < 0:
            raise ValueError("seconds 不能为负数")
```

`__post_init__()` 会在自动生成的 `__init__` 完成后执行，适合检查规则。

重要：dataclass 的类型注解默认不会在运行时强制检查。用户输入、JSON 和 API 响应需要 pydantic，见 02B。
