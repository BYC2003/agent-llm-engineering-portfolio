# 02C：三个入门项目，按小步做出来

前面两份讲义讲了工具和零件，这一册开始组装完整项目。

不要一次把项目全部写完。正确方法是：

```text
先写最小函数
-> 运行一次
-> 写测试
-> 再加下一层
-> 每完成一步就提交 Git
```

三个项目分别训练：

| 项目 | 主要训练 |
|---|---|
| 命令行记账工具 | JSON 存储、业务分层、命令行和测试 |
| 批量文件整理工具 | 文件系统、预览计划、防重名和安全移动 |
| 公开 API 批量查询器 | pydantic、httpx、异步、并发限制和 Mock 测试 |

每个项目都单独建文件夹、单独建 `.venv`，不要把三个项目塞进同一个环境。

> 如果 PowerShell 不允许激活 `.venv`，不用重建环境。把命令里的 `python` 改成：
>
> ```powershell
> & ".\.venv\Scripts\python.exe"
> ```
>
> 这样执行的就是项目自己的 Python。

# 项目 1：命令行记账工具

## 1. 最终效果

用户在终端输入：

```powershell
python main.py add 30 午餐
python main.py add 5000 工资 --kind income
python main.py list
python main.py summary
python main.py --data-file test-data.json list
```

程序应该做到：

- `add`：添加一笔收入和支出，并保存到 JSON。
- `list`：列出所有交易。
- `summary`：显示收入、支出和结余。
- 非法金额：给出能看懂的提示，不直接崩溃。
- pytest：至少有 6 个测试通过。
- README：告诉别人怎样运行。

## 2. 为什么要分层

如果全部写进一个 `main.py`，会出现：

- 参数解析、金额计算、文件读写混在一起。
- 想单独测试金额解析都很难。
- 改命令行显示方式时，容易碰坏存储。

所以按职责拆开：

```text
ledger-cli/
├─ main.py
├─ ledger/
│  ├─ __init__.py
│  ├─ models.py
│  ├─ storage.py
│  ├─ service.py
│  └─ cli.py
├─ tests/
│  ├─ test_service.py
│  ├─ test_storage.py
│  └─ test_cli.py
├─ requirements.txt
├─ .gitignore
└─ README.md
```

| 文件 | 只负责什么 |
|---|---|
| `models.py` | 一笔交易长什么样 |
| `storage.py` | 读写 JSON |
| `service.py` | 金额解析、添加和统计规则 |
| `cli.py` | 命令行参数、打印和错误提示 |
| `main.py` | 调用程序入口 |

判断分层是否正确，可以问：

> 如果明天改成网页界面，`models.py`、`storage.py`、`service.py` 能不能尽量不动？

如果答案是可以，说明职责分得比较清楚。

## 3. 数据格式：金额为什么要用“分”

不要用浮点数保存钱，因为：

```python
0.1 + 0.2
```

结果可能不是精确的 `0.3`。

本项目统一用“整数分”：

- 30 元保存为 `3000`。
- 0.01 元保存为 `1`。
- 显示时再除以 100，变回 `30.00 元`。

JSON 示例：

```json
{
  "version": 1,
  "transactions": [
    {
      "id": "a1b2c3d4e5f6",
      "amount_cents": 3000,
      "note": "午餐",
      "kind": "expense",
      "created_at": "2026-09-25T12:00:00+00:00"
    }
  ]
}
```

## 4. 第一步：先做金额解析

先不要写命令行，也不要写 JSON。只完成一个小函数：

```python
from decimal import Decimal, InvalidOperation


def parse_amount_to_cents(text: str) -> int:
    try:
        amount = Decimal(text)
    except InvalidOperation as exc:
        raise ValueError("金额必须是数字") from exc

    if amount <= 0:
        raise ValueError("金额必须大于 0")

    cents = amount * 100
    if cents != cents.to_integral_value():
        raise ValueError("金额最多保留两位小数")

    return int(cents)
```

逐行理解：

- `Decimal`：比浮点数更适合金钱计算。
- `Decimal(text)`：把用户输入变成十进制数。
- `InvalidOperation`：输入根本不是数字。
- `amount <= 0`：金额必须为正。
- `cents != cents.to_integral_value()`：如果乘 100 后还有小数，说明超过两位小数。
- `int(cents)`：最终变成整数分。

立刻写测试：

```python
import pytest

from ledger.service import parse_amount_to_cents


@pytest.mark.parametrize(
    ("raw", "expected"),
    [
        ("1", 100),
        ("30", 3000),
        ("12.5", 1250),
        ("0.01", 1),
    ],
)
def test_parse_amount(raw: str, expected: int) -> None:
    assert parse_amount_to_cents(raw) == expected


@pytest.mark.parametrize("raw", ["abc", "0", "-1", "1.001"])
def test_parse_amount_invalid(raw: str) -> None:
    with pytest.raises(ValueError):
        parse_amount_to_cents(raw)
```

这里两组测试分别检查：

- 正确输入能不能得到正确金额。
- 错误输入会不会被拦住。
## 5. 第二步：定义交易模型

```python
from dataclasses import dataclass
from datetime import datetime
from typing import Literal
from uuid import uuid4


@dataclass(frozen=True)
class Transaction:
    id: str
    amount_cents: int
    note: str
    kind: Literal["income", "expense"]
    created_at: datetime

    @classmethod
    def create(
        cls,
        amount_cents: int,
        note: str,
        kind: str,
    ) -> "Transaction":
        if amount_cents <= 0:
            raise ValueError("金额必须大于 0")

        if kind not in {"income", "expense"}:
            raise ValueError("kind 必须是 income 或 expense")

        return cls(
            id=uuid4().hex[:12],
            amount_cents=amount_cents,
            note=note.strip(),
            kind=kind,
            created_at=datetime.now().astimezone(),
        )

    def to_dict(self) -> dict:
        return {
            "id": self.id,
            "amount_cents": self.amount_cents,
            "note": self.note,
            "kind": self.kind,
            "created_at": self.created_at.isoformat(),
        }

    @classmethod
    def from_dict(cls, raw: dict) -> "Transaction":
        return cls(
            id=str(raw["id"]),
            amount_cents=int(raw["amount_cents"]),
            note=str(raw["note"]),
            kind=raw["kind"],
            created_at=datetime.fromisoformat(raw["created_at"]),
        )
```

为什么需要 `to_dict()`？

因为 JSON 不认识我们的 `Transaction` 对象。必须先变成字典，再交给 `json.dumps`。

为什么需要 `from_dict()`？

从 JSON 读出来的是普通字典。要重新变成 `Transaction`，才能继续使用对象的方法。

## 6. 第三步：存储层

存储层只做两件事：

1. 从文件加载交易。
2. 把交易保存到文件。

定义业务异常：

```python
class StorageError(Exception):
    """账本文件读写失败。"""
```

读取：

```python
import json
from pathlib import Path


def load_transactions(path: Path) -> list[Transaction]:
    if not path.exists():
        return []

    try:
        raw = json.loads(path.read_text(encoding="utf-8"))
    except (OSError, json.JSONDecodeError) as exc:
        raise StorageError(f"无法读取账本：{path}") from exc

    try:
        return [
            Transaction.from_dict(item)
            for item in raw["transactions"]
        ]
    except (KeyError, TypeError, ValueError) as exc:
        raise StorageError("账本结构不正确") from exc
```

这里分成两段捕获：

- 第一段：文件打不开或 JSON 格式坏。
- 第二段：JSON 能解析，但字段结构不符合要求。

安全保存：

```python
def save_transactions(
    path: Path,
    transactions: list[Transaction],
) -> None:
    path.parent.mkdir(parents=True, exist_ok=True)

    data = {
        "version": 1,
        "transactions": [
            transaction.to_dict()
            for transaction in transactions
        ],
    }

    temp = path.with_suffix(path.suffix + ".tmp")

    try:
        temp.write_text(
            json.dumps(data, ensure_ascii=False, indent=2),
            encoding="utf-8",
        )
        temp.replace(path)
    except OSError as exc:
        raise StorageError(f"无法保存账本：{path}") from exc
```

为什么先写 `.tmp`：

- 如果直接覆盖原账本，写到一半失败可能损坏数据。
- 先写完整临时文件，再替换，更安全。

## 7. 第四步：业务层

```python
def add_transaction(
    path: Path,
    amount_cents: int,
    note: str,
    kind: str,
) -> Transaction:
    transactions = load_transactions(path)
    transaction = Transaction.create(amount_cents, note, kind)
    transactions.append(transaction)
    save_transactions(path, transactions)
    return transaction


def summarize(
    transactions: list[Transaction],
) -> tuple[int, int, int]:
    income = sum(
        transaction.amount_cents
        for transaction in transactions
        if transaction.kind == "income"
    )

    expense = sum(
        transaction.amount_cents
        for transaction in transactions
        if transaction.kind == "expense"
    )

    return income, expense, income - expense
```

关键规则：

- `add_transaction` 不是直接覆盖，而是“加载旧数据 -> 追加 -> 再保存”。
- `summarize` 只做计算，不 `print`。
- 打印属于 CLI 层，业务层只返回结果，方便测试。

## 8. 第五步：命令行入口

```python
import argparse


def build_parser() -> argparse.ArgumentParser:
    parser = argparse.ArgumentParser(

```

运行：

```powershell

```

参数会变成：

```text

note = "午餐"
kind = "expense"
```

`argparse` 负责把用户输入拆成参数，不负责金额规则和文件读写。

## 9. 第六步：把所有层串起来

伪代码：

```text
main():
    解析命令行参数
    把 --data-file 转成 Path

    try:
```

```text

```

# 项目 2：批量文件整理工具

## 1. 最终效果

```powershell
python main.py --source "D:\Downloads" --by extension --dry-run
python main.py --source "D:\Downloads" --by extension
python main.py --source "D:\Downloads" --by date
```

按扩展名整理后：

```text
Downloads/
├─ jpg/
│  ├─ photo.jpg
│  └─ photo_1.jpg
├─ pdf/
│  └─ book.pdf
└─ no_extension/
   └─ README
```

要求：

- `--dry-run` 只预览，不移动任何文件。
- 目标重名时自动加 `_1`、`_2`，不覆盖。
- 单个文件失败不影响其他文件。

## 2. dry-run 为什么重要

移动文件是有副作用的操作。出错后不容易撤销。

dry-run 像出门前先看导航：

```text
先计算“哪个文件准备移到哪里”
-> 用户检查计划
-> 确认后再真正移动
```

这也是 Agent 工具的重要思想：先计划，再执行。

推荐结构：

```text
file-organizer/
├─ main.py
├─ organizer/
│  ├─ __init__.py
│  ├─ planner.py
│  ├─ executor.py
│  └─ cli.py
└─ tests/
   ├─ test_planner.py
   └─ test_executor.py
```

## 3. 计划对象

先描述“准备做什么”，不要马上移动：

```python
from dataclasses import dataclass
from pathlib import Path


@dataclass(frozen=True)
class MovePlan:
    source: Path
    destination: Path


@dataclass(frozen=True)
class MoveResult:
    source: Path
    destination: Path
    ok: bool
    error: str | None = None
```

- `MovePlan`：计划从哪里移动到哪里。
- `MoveResult`：实际执行后成功还是失败。

## 4. 分类规则

按扩展名：

```python
def extension_folder(path: Path) -> str:
    suffix = path.suffix.lower().lstrip(".")
    return suffix if suffix else "no_extension"
```

逻辑：

- `photo.JPG` 的 `.suffix` 是 `.JPG`。
- `.lower()` 变成 `.jpg`。
- `.lstrip(".")` 去掉点，得到 `jpg`。
- 没有扩展名返回 `no_extension`。

按日期：

```python
from datetime import datetime


def date_folder(path: Path) -> str:
    timestamp = path.stat().st_mtime
    return datetime.fromtimestamp(timestamp).strftime("%Y-%m")
```

`st_mtime` 是文件的最后修改时间。

## 5. 防止重名覆盖

```python
def next_available(
    path: Path,
    reserved: set[Path],
) -> Path:
    if not path.exists() and path not in reserved:
        return path

    counter = 1
    while True:
        candidate = path.with_name(
            f"{path.stem}_{counter}{path.suffix}"
        )

        if not candidate.exists() and candidate not in reserved:
            return candidate

        counter += 1
```

需要同时检查：

- `path.exists()`：磁盘上已有同名文件吗？
- `path in reserved`：前面的计划是否已经占用了这个目标？

只看磁盘文件还不够，因为两个源文件可能计划到同一个尚不存在的目标。

## 6. 生成计划

伪代码：

```text
build_plan(source, by):
    检查 source 存在且是目录

    plans = []
    reserved = set()

    for path in source.iterdir():
        如果是目录，跳过
        计算目标目录名
        拼接目标路径
        生成不冲突的目标路径
        加入 plans
        加入 reserved

    return plans
```

建议只扫描一层，因为整理后可能生成 `jpg/`、`pdf/` 等新目录。如果递归扫描，很容易把刚整理好的文件再次移动。

## 7. 执行计划

```python
import shutil


def move_file(source: Path, destination: Path) -> None:
    destination.parent.mkdir(parents=True, exist_ok=True)
    shutil.move(str(source), str(destination))
```

逐个执行并记录失败：

```python
results: list[MoveResult] = []

for plan in plans:
    try:
        move_file(plan.source, plan.destination)
        results.append(
            MoveResult(plan.source, plan.destination, True)
        )
    except OSError as exc:
        results.append(
            MoveResult(
                plan.source,
                plan.destination,
                False,
                str(exc),
            )
        )
```

最后打印：

- 成功数量。
- 失败数量。
- 跳过数量。

## 8. dry-run 的代码边界

```python
if args.dry_run:
    for item in plans:
        print(f"{item.source} -> {item.destination}")
    return 0
```

关键规则：

```text
dry-run 只能调用 build_plan
dry-run 绝对不能调用 move_file
```

## 9. 测试重点

```python
def test_dry_run_does_not_move(tmp_path):
    source = tmp_path / "source"
    source.mkdir()

    file = source / "a.jpg"
    file.write_text("x", encoding="utf-8")

    plans = build_plan(source, "extension")

    assert plans[0].destination == source / "jpg" / "a.jpg"
    assert file.exists()
```

至少测试：

1. `.jpg` 分到 `jpg/`。
2. 无扩展名分到 `no_extension/`。
3. `.JPG` 和 `.jpg` 进入同一组。
4. dry-run 不移动文件。
5. 真正执行时能移动。
6. 重名自动变成 `_1`。
7. 空目录返回空计划。
8. 单个失败不影响其他文件。

## 10. 安全规则

- 只整理用户明确指定的目录。
- 正式执行前先 dry-run。
- 不扫描系统目录。
- 不跟随不可信符号链接。
- 源目录和归档目录重叠时不要递归。
- 绝不覆盖已有文件。
- 失败时保留原文件并记录原因。

## 11. 完成标准

- extension 和 date 两种模式可用。
- dry-run 输出与真实移动目标一致。
- 重名不覆盖。
- 8 个测试通过。
- README 明确提示这是有风险的文件操作。

# 项目 3：公开 API 批量查询器

## 1. 最终效果

```powershell
python main.py --ids 1 2 3 --output posts.json
python main.py --start 1 --end 50 --concurrency 10 --output posts.json
```

要求：

- 使用 httpx 异步客户端。
- 设置超时。
- 限制并发。
- 一条失败不影响整批。
- 输出成功和失败统计。
- 测试使用 MockTransport，不依赖真实网络。

练习接口：

```text
https://jsonplaceholder.typicode.com/posts/{id}
```

## 2. 结构

```text
bulk-api-query/
├─ main.py
├─ query_app/
│  ├─ __init__.py
│  ├─ models.py
│  ├─ client.py

│  └─ cli.py
└─ tests/
   ├─ test_models.py

```

职责：

- `client.py`：发 HTTP 请求。
- `service.py`：批量查询、汇总、去重。
- `cli.py`：接收参数并显示结果。
- `main.py`：调用入口。

## 3. 用 pydantic 定义返回结构

```python
from pydantic import BaseModel, Field


class Post(BaseModel):
    id: int
    user_id: int = Field(alias="userId")
    title: str
    body: str
```

API 返回的字段是 `userId`，Python 内部使用 `user_id`。如果返回缺字段，pydantic 会报错，而不是等到后面访问时突然崩溃。

## 4. 单条获取

```python
import asyncio
import httpx


async def fetch_post(
    client: httpx.AsyncClient,
    post_id: int,
    semaphore: asyncio.Semaphore,
) -> dict:
    async with semaphore:
        response = await client.get(f"/posts/{post_id}")
        response.raise_for_status()

        post = Post.model_validate(response.json())
        return post.model_dump()
```

步骤：

1. 进入并发信号量。
2. 等待请求完成。
3. 状态码失败时抛错。
4. 用 pydantic 校验 JSON。
5. 转成普通字典返回给上层。

## 5. 批量并发

```python
semaphore = asyncio.Semaphore(10)

async with httpx.AsyncClient(
    base_url="https://jsonplaceholder.typicode.com",
    timeout=httpx.Timeout(10.0),
) as client:
    tasks = [
        fetch_post(client, post_id, semaphore)
        for post_id in range(1, 21)
    ]

    results = await asyncio.gather(
        *tasks,
        return_exceptions=True,
    )
```

含义：

- `tasks` 是 20 个待执行任务。
- 信号量最多允许 10 个同时运行。
- `gather` 等待整批完成。
- `return_exceptions=True` 让异常也成为结果，便于逐条统计。

## 6. 汇总成功和失败

```python
succeeded = []
failed = []

for post_id, result in zip(range(1, 21), results):
    if isinstance(result, Exception):
        failed.append(
            {"id": post_id, "error": str(result)}
        )
    else:
        succeeded.append(result)

output = {
    "total": 20,
    "success": len(succeeded),
    "failed": len(failed),
    "posts": succeeded,
    "errors": failed,
}
```

`zip` 把原始 ID 和对应结果配成一对，这样即使某条失败，也知道是哪一个 ID 失败。

## 7. 写入 JSON

复用 02A 的安全写入：

- 构造 Python 字典。
- `json.dumps(..., ensure_ascii=False, indent=2)`。
- 先写临时文件。
- 再替换正式文件。

输出中不要写：

- API Key。
- Cookie。
- 完整认证请求头。

这些信息可能被误提交或泄露。

## 8. 重试规则

可以重试：

- 连接超时、读取超时。
- `429`。
- `502`、`503`、`504`。

异步等待：

```python
await asyncio.sleep(wait_seconds)
```

不要在有异步事件循环时使用 `time.sleep()`，它会卡住整个程序。

其他规则：

- 最多重试 3 次。
- 使用指数退避。
- 理想情况下遵守 `Retry-After`。
- 非幂等 POST 不盲目重试。

## 9. 用 MockTransport 测试

假服务器：

```python
import httpx


def handler(request: httpx.Request) -> httpx.Response:
    post_id = int(request.url.path.rsplit("/", 1)[-1])

    return httpx.Response(
        200,
        json={
            "id": post_id,
            "userId": 1,
            "title": "hello",
            "body": "world",
        },
    )
```

创建假客户端：

```python
transport = httpx.MockTransport(handler)

async with httpx.AsyncClient(
    transport=transport,
    base_url="https://fake.test",
) as client:
    result = await fetch_post(
        client,
        7,
        asyncio.Semaphore(1),
    )

    assert result["id"] == 7
```

这样测试不会真的访问互联网，速度快且稳定。

至少测试：

1. 正常响应能转成 `Post`。
2. 缺字段触发 `ValidationError`。
3. `404` 转成友好错误。
4. `429` 重试后成功。
5. 多次超时后失败。
6. 输入 ID 与输出对应。
7. 重复 ID 去重。
8. 部分失败仍能生成结果。
9. 成功、失败数量正确。
10. 输出 JSON 能被 `json.loads` 解析。

## 10. 常见坑

- 异步代码里混用 `requests`。
- 忘记设置超时。
- 并发太高，被服务器限流。
- 一条异常让整批失败。
- 测试依赖真实网络，偶尔通过、偶尔失败。
- API 返回结构变了却直接访问字段，没有 pydantic 校验。
- 把密钥写进代码或结果文件。
- 使用 `time.sleep()` 阻塞异步事件循环。
